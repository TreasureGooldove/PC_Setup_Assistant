# 探索结论

## 现状

- 统一目录已有 CPU、显卡、主板扩展数据，但内存、硬盘、电源、散热和机箱只有 2 到 3 个候选。
- `PartPicker` 已有关键词、品牌下拉和价格输入，但缺少快捷筛选、图片、来源状态和候选更新入口。
- SQLite 任务队列已有幂等、租约、重试、死信、取消、背压和 SSE，可直接承载目录同步。
- `Part` 已有图片、来源、URL、摘要和更新时间字段，缓存无需另造展示模型。

## 交互证据

- 公开装机选配样本采用关键词、最低/最高价、品牌快捷项、型号系列快捷项和高密度商品行。
- ZOL 各产品列表页提供公开产品名称、摘要、参考价、图片和详情链接，适合作为可选候选发现来源。
- 列表页使用 GBK 响应，产品节点有稳定的产品 ID、图片、标题与参考价结构；解析失败必须回退。

## 方案

- 新增 `catalog_sync` 功能模块，负责白名单 URL、HTML 解析、缓存、合并、筛选与分面。
- 新增 `catalog_parts` 与 `catalog_sync_states` 表，缓存只保存标准化 `Part` 和同步状态。
- `GET /api/catalog/{category}` 返回候选、品牌/类型分面和同步状态；`POST .../refresh` 创建后台同步任务。
- 前端选择器改为可提交的筛选工具栏、快捷筛选芯片、同步状态与带图片候选列表。
