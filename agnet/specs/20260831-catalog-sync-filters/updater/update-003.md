# 功能更新方案

## 1. 更新背景

需求参数页的“生成我的方案”按钮点击后缺少明确的页面反馈；演示数据与已有方案相近时，用户容易误以为按钮没有生效。当前预算主要依赖滑块，无法精确输入自定义金额，也不方便处理超过滑块常用范围的预算。

## 2. 更新目标

- 修复生成按钮的交互链路，点击后立即展示进度、处理中状态和完成反馈。
- 生成完成后将用户视线带到方案工作台，避免结果更新发生在当前视口之外。
- 为预算增加可编辑的数字输入框，支持精确金额、中文金额校验和边界提示。
- 滑块与数字输入双向同步；预算变化后仍通过现有对话、API、方案生成和兼容性流程。
- 保留 API/Worker 生成逻辑与离线演示降级，不改变价格和硬件数据边界。

## 3. 实现范围

- `apps/web/src/App.tsx`：补充预算输入状态、统一预算规范化、生成按钮可见反馈和结果定位。
- `apps/web/src/styles.css`：增加预算输入组合布局、校验状态和生成反馈样式，兼容移动端。
- `apps/web/src/App.test.tsx`：覆盖自定义预算、范围校验、按钮点击后的进度与完成结果。
- `plan.md` 与当前 Spec 更新记录：同步真实完成状态，不记录内部逐步思考原文。

## 4. 验收标准

- [x] 点击“生成我的方案”后立即出现生成中状态或进度区域，按钮不会表现为无响应。
- [x] 演示模式生成完成后显示完成反馈，并定位到方案工作台；API 模式保持轮询、SSE 和错误提示。
- [x] 可在预算输入框输入精确到 1 元的金额，最低 2500 元；非法、空值和超出上限的输入会给出明确提示或安全收敛。
- [x] 滑块、数字输入、自然语言预算和生成请求使用同一个规范化预算值。
- [x] 既有需求对话、方案切换、导出、兼容性检查和 API 不可用时的演示模式回归通过。
