# 功能更新方案

## 文档关联

- 原设计：[[../writer/plan|设计方案]]
- 原总结：[[../executor/implementation-summary|实现总结]]

## 1. 更新背景

### 1.1 问题描述

当前候选列表直接显示厂商与目录参考价，但右侧详情没有京东、拼多多的价格与状态。用户必须再进入独立商品详情页才能比价，不符合“选中候选后立即核对平台信息”的操作预期；同时需要为淘宝商品详情保留可配置的实时数据入口，避免将本地示例金额误认为真实成交价。

### 1.2 影响范围

- `App.tsx` 的候选报价加载状态与异步请求编排。
- `PartPicker.tsx` 的选择事件和右侧详情展示。
- 商品报价展示组件与相关样式、测试。
- 淘宝 MCP sidecar 配置、标准 MCP 会话、结果解析和实时价开关。

## 2. 更新目标

### 2.1 主要目标

- 选中任一候选后，在右侧详情同屏显示京东和拼多多两组报价。
- 接入可选淘宝 MCP：按内部配件 ID 映射具体淘宝/天猫商品引用，展示返回的店铺、SKU、参数、价格和采集时间。
- 选中任一候选后，在右侧详情同屏显示完整的结构化配置参数，至少覆盖当前数据中已有字段。
- 每组展示平台、参考到手价、划线价、店铺/来源、实时或示例状态、采集时间和平台核价入口。
- 切换候选时异步更新报价，避免慢请求覆盖后选中的型号；加载失败时使用现有离线报价并保持明确状态。
- 复用现有 `ProductDetail.offers` 和 `/api/products/{part_id}`，不新增重复后端模型。

### 2.2 非目标

- 不把示例报价描述为实时成交价或最低价。
- 不新增验证码绕过、支付或自动下单。
- 淘宝 MCP 只作为用户单独安装的 sidecar 连接器；不复制第三方抓取代码，不绕过登录、验证码、访问控制或反爬。

## 3. 更新方案

### 3.1 方案概述

将平台报价卡提取为可复用展示组件。`App` 在打开选配器和切换候选时调用现有商品详情接口，仅把 `offers` 传给 `PartPicker`；接口不可用时使用 `localProductDetail` 生成的明确“示例报价（未联网）”。后端增加淘宝 MCP 标准 stdio 客户端和 `REALTIME_PRICES_REQUIRED` 严格模式，未拿到可核验实时金额时不返回示例报价。

### 3.2 详细设计

#### 3.2.1 报价状态编排

**文件**：`apps/web/src/App.tsx`

- 新增候选报价、加载状态和当前请求标识。
- 打开选配器后加载当前候选报价；切换候选时重新加载。
- 用递增请求标识丢弃过期响应，关闭弹窗时清理可见状态。

#### 3.2.2 同屏报价组件

**文件**：`apps/web/src/features/catalog/OfferComparison.tsx`、`PartPicker.tsx`、`ProductDetailPage.tsx`

- 提取京东/拼多多报价卡，复用于独立商品页和候选详情。
- 候选详情在规格与点评前显示紧凑双平台报价，并提供完整参数网格。
- `is_live=false` 时显示“示例 / 未联网”，并保留平台核价链接。

#### 3.2.4 淘宝 MCP 实时数据

**文件**：`apps/api/app/features/products/taobao_mcp.py`、`apps/api/app/config.py`、`apps/api/app/features/products/service.py`

- 使用 MCP Python SDK 连接外部 `server.py`，复用持久化 MCP 进程和浏览器会话；首次调用按服务约定初始化登录。
- 支持 `taobao_fetch_product`，并兼容旧的 `taobao_fetch_product_info` 工具名；按分页元数据合并返回的参数。
- 只接受数字商品 ID、淘宝/天猫 HTTPS 链接或包含允许域名的分享文本；结果需解析出明确金额后才标记 `is_live=true`。
- 真实价格模式开启时，京东/拼多多未取得授权报价也不返回 Fixture 金额；状态区标记未获取实时价。

#### 3.2.3 视觉与无障碍

**文件**：`apps/web/src/styles.css`

- 企业简洁主题下保持现有蓝色层级，京东与拼多多使用平台文字区分，不复制平台受保护素材。
- 按钮触控区不小于 44px，加载状态使用 `aria-live`，小屏改为单列。

### 3.3 数据结构变更

复用 `Offer` 与 `ProductDetail`；新增 `mcp` Python SDK 运行依赖和淘宝 MCP 本地配置项，不改变公开响应模型。

### 3.4 接口变更

无。复用 `GET /api/products/{part_id}`。

## 5. 风险评估

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 快速切换候选导致报价错位 | 展示错误型号的价格 | 使用请求标识，仅接收最后一次选择的响应 |
| 示例价被误解为实时价 | 误导购买判断 | 同时展示 `is_live`、状态文字、采集时间和“前往平台核价” |
| 详情区变长 | 小屏操作拥挤 | 紧凑卡片、独立滚动区与移动端单列 |
| MCP 未登录或第三方工具版本不同 | 无法读取实时淘宝数据 | 自动识别新旧工具名，区分未配置/未登录/解析失败，不用示例金额冒充实时价 |

### 5.1 回滚方案

移除候选详情中的报价组件与加载状态，独立商品详情页继续保留既有比价功能。

## 6. 验收标准

- [ ] 选择任一候选后，无需离开弹窗即可看到京东和拼多多价格。
- [ ] 两个平台均显示来源/店铺、状态、采集时间和核价链接。
- [ ] 示例数据明确显示“示例报价（未联网）”，不出现实时价误导。
- [ ] 淘宝 MCP 取得明确金额后显示店铺、SKU、实时状态、采集时间和参数；未授权时显示未获取实时价。
- [ ] `REALTIME_PRICES_REQUIRED=true` 时无授权报价不返回示例金额。
- [ ] 快速切换候选不会出现型号与报价错配。
- [ ] 候选详情可以查看完整配置参数，数组、布尔值和单位按统一格式展示。
- [ ] 既有筛选、同步、商品详情、换件与兼容性流程正常，回归测试全部通过。
