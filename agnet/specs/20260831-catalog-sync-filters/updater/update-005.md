## 1. 更新背景

### 1.1 问题描述

当前输入区能够解析预算、用途和游戏，但用户看不到“为什么这样选”的结构化说明。方案工作台已有配件、报价来源、游戏配置和兼容性检查结果，却没有把这些已验证信息汇总成一份可读的建议，模型能力也没有形成可控的产品闭环。

用户希望把需求、游戏最低/推荐配置、候选配件、价格来源和兼容性结果交给 Qwen，生成建议配置说明。该能力必须保留离线演示，不能让模型直接决定硬件、价格或兼容性，也不能展示模型隐藏的逐步思考原文。

### 1.2 影响范围

- 前端需求对话和方案工作台：展示“AI 辅助建议”及结构化依据。
- 后端模型适配、建议服务、上下文工具和现有任务队列：生成并传输建议结果。
- API 类型、配置项、测试和 README：说明模型开关、降级行为与数据边界。

---

## 2. 更新目标

### 2.1 主要目标

- 在用户提交需求和生成方案后，展示结构化的建议配置摘要：需求理解、方案定位、核心选择理由、兼容性结论、价格来源和待确认项。
- 预留 Qwen OpenAI 兼容接口，模型名默认使用 qwen3.8-max；未配置凭证或调用失败时，使用确定性 Mock 建议，不阻塞方案生成。
- 建立服务端受控上下文工具层，统一提供需求、游戏配置、候选配件、兼容性和报价证据；工具只读、固定白名单、限制字段与长度，不允许模型任意访问数据库、网络或执行代码。
- 使用 Pydantic 结构化输出并进行二次校验：配件只能来自当前方案，价格只能来自已验证报价/参考价，兼容性结论只能引用规则检查结果。
- 通过现有任务进度/SSE 展示“整理资料—生成建议—校验结果—完成”的阶段状态，避免用户看到无反馈的等待。
- 支持重新生成建议、查看证据和回到游戏/商品详情；界面明确标注“AI 辅助建议”和数据来源。

### 2.2 非目标（明确不做的事情）

- 不展示或保存模型隐藏链式思考、内部 token、系统提示词、工具调用原始日志或密钥。
- 不让模型替换配件、修改价格、跳过兼容性硬规则、执行下单或直接抓取平台。
- 不在本次更新实现新的电商爬虫、验证码绕过、登录态操作或任意第三方 MCP 执行器。
- 不要求配置 Qwen 密钥才能运行本地演示、测试和 CI；用户密钥只允许通过本机未跟踪 .env 注入。

## 3. 更新方案

### 3.1 方案概述

采用“确定性数据准备 → 白名单工具上下文 → 可选模型解释 → Pydantic 校验 → 结构化 UI 展示”的链路。硬件候选、预算、平台报价、游戏需求和兼容性检查由现有服务产生；模型仅将这些事实组织成面向用户的解释，并输出有限字段。建议任务复用 SQLite 队列与 SSE，模型不可用时返回 Mock 结果并标注来源。

### 3.2 详细设计

#### 3.2.1 结构化建议领域模型

文件：apps/api/app/domain.py、apps/web/src/types.ts

新增 Recommendation、RecommendationDecision、RecommendationEvidence 和 RecommendationStatus 等类型，至少包含：

- headline、summary、profile_summary：用户可直接阅读的结论。
- decisions：配件槽位、当前方案配件 ID、选择理由、依据引用 ID。
- compatibility_summary：通过项、警告项、错误项及对应规则引用。
- price_summary：总价、预算关系、报价状态；没有核验金额时显示待联网/参考状态。
- uncertainties、next_actions：待确认字段和用户下一步操作。
- provider、generated_at、source_status：标识 Mock、Qwen 或失败回退，不伪装成真人结论。

模型中不设置 thoughts、chain_of_thought 等字段；服务端拒绝未知字段，前端只渲染上述白名单字段。

#### 3.2.2 受控上下文工具与模型适配器

文件：apps/api/app/features/recommendations/

- tools.py：提供固定工具 get_need_profile、get_game_requirements、get_plan_items、get_compatibility_result、get_price_evidence。每个工具只返回当前会话/方案的最小必要字段，并统一截断长文本。
- service.py：编排工具结果，组装版本化 RecommendationContext，调用模型后执行确定性校验；业务逻辑不进入 HTTP 层。
- providers.py：定义 RecommendationProvider 接口，实现 MockRecommendationProvider 和可选 QwenRecommendationProvider。如后续接入 MCP，使用相同的只读工具协议和白名单，不开放任意工具名。
- schemas.py：定义模型 JSON schema、解析和校验错误；模型输出无效时回退 Mock，并记录面向用户的可读状态。

#### 3.2.3 Qwen 调用边界

文件：apps/api/app/llm.py、apps/api/app/config.py

- 复用 OpenAI 兼容客户端，增加建议生成方法，使用结构化 JSON 输出、低温度和有限输出长度。
- 提交给模型的内容只包含脱敏后的需求、当前方案、商品参数、报价状态、游戏公开配置和兼容性结果；不提交数据库连接、环境变量、工具凭证或内部日志。
- 模型提示明确：只能引用上下文事实，缺失字段写“待确认”，不要输出隐藏思考，不得编造价格/店铺/兼容性。
- LLM_ENABLED=false 或 API Key 缺失时不发起网络请求；超时、限流、解析失败均降级为 Mock 建议。

#### 3.2.4 API 与队列

文件：apps/api/app/main.py、apps/api/app/features/jobs/service.py、apps/api/app/queue.py

新增：

| 接口 | 变更类型 | 说明 |
|---|---|---|
| POST /api/plans/{plan_id}/recommendations | 新增 | 校验方案存在后创建幂等建议任务；演示方案沿用前端本地 Mock，不把未持久化 ID 发给后端 |
| GET /api/recommendations/{id} | 新增 | 返回已校验的结构化建议及来源状态 |

任务结果继续使用 GET /api/jobs/{id} 和 /events，事件只发送阶段、进度和完成状态，不发送模型 token 流或原始提示词。任务失败保留明确错误与重试入口。

#### 3.2.5 前端展示

文件：apps/web/src/App.tsx、apps/web/src/features/recommendations/RecommendationCard.tsx、apps/web/src/styles.css

- 输入提交后在需求面板显示“正在整理需求”状态；生成方案后在方案工作台显示带 AI 标识的建议卡片。
- 建议卡片按“结论—配置取舍—兼容性—价格与来源—待确认—下一步”分组，长内容折叠展示，避免一屏堆满。
- 每个关键结论显示来源标签，可打开游戏配置、商品详情或兼容性检查；不以颜色作为唯一状态。
- 提供重新生成、查看来源和关闭/展开控制；加载、空结果、错误、离线 Mock 均有明确反馈。
- 动态结果使用 aria-live="polite"，按钮最小触控区 44px，遵循当前企业简洁风与可切换主题，不使用 emoji 作为图标。

### 3.3 数据结构变更

- 新增结构化建议响应，不改动既有 BuildPlan 的硬件和价格字段。
- Job.result 增加 recommendation_id/recommendation 可选字段，保持旧任务结果兼容。
- 不保存模型原始响应；只保存通过校验的建议字段和来源引用。

### 3.4 接口变更

| 接口 | 变更类型 | 说明 |
|---|---|---|
| POST /api/plans/{plan_id}/recommendations | 新增 | 异步生成建议，支持 Idempotency-Key |
| GET /api/recommendations/{id} | 新增 | 获取结构化、已校验建议 |
| GET /api/jobs/{id} | 兼容扩展 | 任务完成结果允许携带建议 ID |
| GET /api/jobs/{id}/events | 兼容扩展 | 增加建议阶段事件，禁止输出 token/提示词 |

## 5. 风险评估

### 5.1 潜在风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 模型编造型号、价格或兼容性结论 | 用户误购或错误装机 | 只允许引用上下文 ID；服务端校验配件、金额和规则结果；无依据显示待确认 |
| Qwen 服务超时或不可用 | 建议等待或页面空白 | Mock 降级、任务状态、超时提示和重新生成入口 |
| 上下文过大或包含敏感数据 | 成本、泄露和响应失败 | 工具最小字段、长度限制、脱敏和不保存原始请求 |
| 建议结果与用户替换后的方案不一致 | 解释过期 | 方案版本/指纹绑定；换件或刷新报价后标记过期并要求重新生成 |
| 流式输出暴露内部内容 | 泄露提示词或隐藏思考 | 只流式发送阶段状态；最终只传递 Pydantic 校验后的字段 |

### 5.2 回滚方案

1. 关闭 LLM_ENABLED，保留 Mock 建议和现有确定性方案生成。
2. 停止建议任务入口，前端隐藏建议卡片，保留配件、兼容性和导出功能。
3. 删除建议缓存/任务记录时只清理本次新增数据，不修改既有方案和报价数据。

## 6. 验收标准

- [x] 输入预算、游戏和偏好后，页面能显示一份带“AI 辅助建议”标识的结构化建议，不展示隐藏思考原文。
- [x] 建议至少包含需求摘要、方案定位、核心配件选择理由、兼容性状态、预算/价格来源和待确认项。
- [x] Qwen 未配置、网络失败或输出非法时，仍能通过 Mock 完成建议展示，并清楚标注为本地演示/降级结果。
- [x] 模型不能输出当前方案之外的配件、未经验证的价格或覆盖硬件兼容性规则的结论；非法结果被拒绝或降级。
- [x] 自制工具/MCP 仅能调用固定只读白名单，不允许任意网络、数据库、命令或登录态操作。
- [x] 建议任务支持幂等、进度/SSE、失败重试和重新生成；换件/刷新报价后旧建议被标记过期。
- [x] UI 具备加载、空、错误、离线、键盘焦点和可访问动态状态；不使用 emoji 图标，触控目标不小于 44px。
- [x] 后端 Ruff、mypy、Pytest 与前端类型检查、Vitest、生产构建全部通过，既有功能回归通过。
