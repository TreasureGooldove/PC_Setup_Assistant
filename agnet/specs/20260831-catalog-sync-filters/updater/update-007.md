## 1. 更新背景

### 1.1 问题描述

当前首页存在两个容易让用户犹豫的入口：顶部输入框的“告诉我”只更新需求，下面的“生成我的方案”才真正生成配置。用户输入预算和游戏需求后，如果没有再次点击第二个按钮，会误以为系统没有响应。

用户希望流程更接近装机问答工具的自然逻辑：先提交完整需求，系统自动整理问题、资料和候选配件，然后进入能够逐项核对的方案工作台。参考公开装机问答产品的“提问—答复—依据”关系，但不复制其品牌、素材、页面文案或实现。

### 1.2 影响范围

- 首页需求输入表单和主操作按钮。
- 对话提交、结构化需求更新、游戏识别与方案生成的状态传递。
- Agent 摘要面板、进度反馈、方案工作台定位。
- 前端交互测试、文档和脱敏 Spec 记录。

---

## 2. 更新目标

### 2.1 主要目标

- 合并顶部“告诉我”和“开始生成可核对方案”的语义，主按钮显示为“告诉我并生成可核对方案”。
- 用户提交非空需求后，自动执行：解析需求 → 更新对话 → 生成三套方案 → 生成结构化建议 → 滚动到方案工作台。
- 自动生成必须使用本次刚解析的预算、用途、偏好和游戏标识，不能等待 React 异步状态更新，也不能被 API 初始化结果覆盖。
- 保留方案参数区的手动生成入口，用于用户修改预算、分辨率、品牌、散热或机身尺寸后的再次核对；按钮文案改成“重新生成并核对”。
- 输入区继续展示可审计阶段摘要、进度、成功/失败和离线状态；不能展示隐藏思考原文或原始模型日志。
- API 不可用时，自动流程仍使用本次输入生成本地演示方案，并明确显示离线状态。

### 2.2 非目标

- 不在用户每次击键时触发网络请求或生成任务；以提交表单/按 Enter 作为“输入完成”信号。
- 不删除方案工作台、配件替换、锁定、兼容性检查、商品详情、导出、天梯图、游戏配置或 Agent 摘要功能。
- 不复制参考站点的品牌标识、角色素材、页面源码、受保护文案或数据接口。

## 3. 更新方案

### 3.1 方案概述

将需求提交处理收敛为一个异步流程。`handleSend` 先在局部变量中得到最新 `NeedProfile` 和游戏识别结果，再把这些值显式传给生成函数；生成函数不依赖尚未完成的 React state 更新。顶部 CTA 只负责提交并触发该流程，底部 CTA 继续用于参数调整后的手动重算。

### 3.2 详细设计

#### 3.2.1 顶部输入 CTA

**文件**：`apps/web/src/App.tsx`

**修改内容**：将“告诉我”改为“告诉我并生成可核对方案”，提交按钮在生成期间禁用并显示当前阶段；提交后立即启动自动生成。

**修改原因**：消除“需求已更新但没有方案”的断点，让用户知道提交动作已经包含生成动作。

#### 3.2.2 最新状态显式传递

**文件**：`apps/web/src/App.tsx`

**修改内容**：生成函数接收本次解析的 profile、conversation、game requirement 和本地降级标记；推荐任务同样接收本次游戏识别结果。

**修改原因**：避免预算、游戏配置或 API 对话结果因异步 state 更新时序而丢失。

#### 3.2.3 可核对结果反馈

**文件**：`apps/web/src/features/recommendations/RequestInsightPanel.tsx`、`apps/web/src/styles.css`

**修改内容**：将摘要文案、成功反馈和方案工作台定位统一为“可核对方案”；保留加载、失败、离线和重试状态，补充 `aria-live`/`aria-busy` 语义。

**修改原因**：参考“问题—答复—依据”的交互关系，但将答复落到本项目的结构化配置和兼容性检查上。

#### 3.2.4 测试与文档

**文件**：`apps/web/src/App.test.tsx`、`apps/web/src/features/recommendations/RequestInsightPanel.test.tsx`、`README.md`、`plan.md`、本目录 summary。

**修改内容**：覆盖提交一次即触发生成、精确预算和游戏标识传递、按钮忙碌状态、离线降级、结果定位；补充启动和流程说明。

### 3.3 数据结构变更

无数据库结构变更。仅扩展前端内部函数参数，不改变公开 API 契约。

### 3.4 接口变更

| 接口 | 变更类型 | 说明 |
|------|----------|------|
| `POST /api/conversations/{id}/messages` | 无 | 继续更新结构化需求 |
| `POST /api/conversations/{id}/generate` | 无 | 自动流程复用现有异步生成任务 |
| `POST /api/plans/generate` | 无 | 方案推荐和 Agent 摘要继续复用现有接口 |

## 5. 风险评估

### 5.1 潜在风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 自动生成等待时间较长 | 用户误以为页面卡住 | CTA 忙碌态、阶段进度、`aria-busy` 和错误/重试状态 |
| 用户连续提交造成重复任务 | 方案结果互相覆盖 | 生成期间禁用 CTA、请求序号和现有任务取消机制 |
| API 初始化与用户提交竞争 | 用户输入或游戏标识丢失 | 使用局部最新值传递，初始化只在用户未交互时写入 profile |
| 参考页面逻辑被误解为复制 | 产品边界不清 | 只借鉴提问—答复—依据的交互关系，保留独立视觉与数据实现 |

### 5.2 回滚方案

1. 恢复顶部 CTA 为原文案并移除提交后的自动 `handleGenerate` 调用。
2. 保留现有手动“生成我的方案”入口和 Agent 摘要，确保用户仍可手动生成。
