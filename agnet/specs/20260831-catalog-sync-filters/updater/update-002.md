# 功能更新方案

## 1. 更新背景

候选和商品详情原先以平铺卡片展示已有字段，缺少 CPU、显卡、主板、内存、存储、电源、散热和机箱的统一参数目录。商品页新增的字段也难以与已有结构化字段区分，无法快速判断哪些参数已采集、哪些仍需要人工核对。

## 2. 更新目标

- 按配件类别提供分组参数 schema，覆盖身份、性能、接口、尺寸、供电、散热和售后等常用字段。
- 候选详情和商品详情复用同一张参数表，显示已采集值、单位和待确认字段数量。
- 保留商品页返回的未归一化字段，并以“其他已采集字段”展示，不丢失来源信息。
- 京东常见中文参数映射到统一字段；淘宝 MCP 即使没有返回价格，只要返回参数也应保留。
- 不为缺失字段推测或填充未经来源验证的硬件数据。

## 3. 实现范围

- `partFormat.ts`：新增类别参数分组、字段标签、别名、单位格式化和采集状态统计。
- `DetailedSpecTable.tsx`：新增可复用的分组表格，紧凑模式用于候选弹窗。
- `PartPicker.tsx`、`ProductDetailPage.tsx`：传入品牌、型号和参考功耗，并接入统一参数表。
- `styles.css`：增加表头、分组、待确认状态和响应式表格样式，兼容企业简洁主题。
- `products/service.py`：补齐京东常见硬件参数映射；淘宝参数不再依赖实时价格才能进入详情数据。

## 4. 验收标准

- [ ] CPU 详情至少能展示插槽、架构、制程、核心线程、基础/加速频率、缓存、功耗、核显和内存支持字段。
- [ ] 显卡详情至少能展示芯片、显存容量/类型/位宽、PCIe、视频输出、供电、长度、功耗和建议电源字段。
- [ ] 主板、内存、存储、电源、散热和机箱均有独立分组，不与其他类别共用错误字段。
- [ ] 缺失参数显示“待确认”，并显示已采集/待确认数量；不得以“待确认”之外的默认值冒充真实数据。
- [ ] 京东和淘宝返回的已知与未知参数均能进入详情展示。
- [ ] 候选详情、商品详情、筛选、换件、报价和兼容性流程不受影响。
